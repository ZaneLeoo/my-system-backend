# 采购入库与数量库存一期

## 边界与单据

业务位于既有业务模块的 `purchase.receipt` 和 `inventory`。入库只能参照已审核到货行，来源采购订单关闭不影响入库；同一张入库单限定供应商及仓库，允许合并多张到货单、分批办理及拆分到不同货位。每单最多 200 行，同一来源与货位不可重复，无货位仓库的货位必须为空。

`purchase_receipt` 保存 PR 单号、业务日期、供应商及仓库快照、货位管理方式、经办与部门快照、状态、版本和动作信息；`purchase_receipt_line` 保存稳定行 ID、来源到货和订单追溯信息、料品及单位快照、货位快照、数量与来源精度。业务日期不得早于到货日期。更新保留行 ID，移除明细使用带实体的逻辑删除及公共审计。

数量以 BigDecimal 和十进制字符串传输；单据使用 DECIMAL(15,6)，余额与流水使用 DECIMAL(20,6)。超出来源数量精度、库存上限或版本上限时拒绝，不静默舍入。库存单位固定为料品基本单位。一期无价格、成本、凭证、单位换算、批次、序列号、质检、退货、出库、调拨或期初导入。

## 生效与冲销

到货行的 `pending_receipt_quantity` 和 `received_quantity` 分别表示待审核入库和已入库，默认零，数据库限制非负且合计不超过到货数量。来源可新增数量是到货数量减两者。同一来源的拆分行先聚合再校验、反写。

| 命令 | 状态变化 | 来源到货行 | 库存 |
| --- | --- | --- | --- |
| 保存／修改 | 草稿 | 校验余量，不占用 | 不变 |
| 提交 | 草稿 → 已提交 | 增加待审核数量 | 不变 |
| 撤回／驳回 | 已提交 → 草稿 | 释放待审核数量 | 不变 |
| 审核 | 已提交 → 已审核 | 待审核转已入库 | 加余额、写正向流水 |
| 作废 | 已审核 → 已作废 | 冲减已入库 | 扣余额、追加关联原流水的冲销 |
| 删除 | 仅草稿 | 不变 | 不变 |

驳回、作废必须填写原因。重复或过期命令拒绝，不重复记账。每次单据动作递增版本，每张被反写的来源到货单只递增一次版本。到货单派生未入库／部分入库／全部入库进度，不合计不同单位；不再次修改订单到货累计数，也不自动关闭上游。

`ReceiptService.transition` 是整单状态入口；`InventoryPostingService` 强制加入调用方事务，统一写余额和流水，没有公开库存写接口。采购相关写入沿用分类树事务锁，来源主表／行、仓库、货位、单位、料品及余额使用当前读；同类对象按固定维度或 ID 顺序加锁。仓库锁协调货位及仓库维护，唯一索引兜底余额初始化。状态、执行量、版本、审计、余额和流水任一失败全部回滚。

库存余额维度为仓库、料品、货位。数据库生成 `location_key=COALESCE(location_id,0)`，唯一索引防止多个 NULL 货位余额；0 不作为外部货位 ID。余额零值保留，余额及流水继承 AuditEntity，无逻辑删除。正向流水按业务类型与入库行唯一，冲销按原流水 ID 唯一，原流水不修改。冲销使用原维度、数量及快照，库存不足整单拒绝；不因档案停用阻止退回或冲销。

当前余额按实际审核时点变化，不是业务日期的历史时点余额。正常流水业务日期取入库日期，冲销取当天北京时间日期；实际记账时间独立记录。后续出库、调拨、退货应扩展统一库存命令及下游引用校验，不直接更新余额。

## 档案引用

公共引用 Mapper 统一处理采购订单、到货、入库及库存历史，档案维护服务不依赖采购 Service。到货存在未删除且未作废入库单（含草稿）时禁止作废。待处理到货按实际剩余量判断，全部入库不会永久阻止停用。

未完成入库及正库存阻止相关仓库、货位、料品停用；库存单位也检查库存占用。正库存本身不阻止关闭料品采购开关，未完成采购业务仍会阻止。历史入库或流水阻止相关档案删除、料品库存单位变更；已保存入库单或库存历史固定仓库的货位管理方式。

## 接口、权限及迁移

维护前缀 `/purchase/receipt`：list、详情、defaults、POST、PUT、按版本 DELETE，以及 submit／withdraw／approve／reject／void 命令。使用 `purchase:receipt` 独立动作权限。列表按单号、供应商、仓库、状态、日期和来源到货筛选，排序仅允许单号、业务日期、修改时间并追加 ID。

`/purchase/arrival/reference-lines` 及 `/resolve?ids=...` 使用独立 `purchase:arrival:reference`，不要求到货维护权限。参照返回可新增来源的必要字段，无金额和审计；批量复核每次 1～100 个不同正 ID。

`/inventory/balance/list` 与 `/inventory/transaction/list` 分别使用 `inventory:balance:list` 和 `inventory:transaction:list`，不依赖基础档案参照权限，也不隐藏停用档案。支持料品关键词、仓库／货位编码；余额默认仅显示正库存，支持数量排序；流水支持单号、类型、记账时间及稳定时间排序。库存维度跳转参数可限定仓库、料品、货位或无货位，不把 NULL 维度混入其他货位。

所有新接口返回 R，分页为 PageResult 的 rows、total，默认 20、最多 100，排序使用白名单，手写 SQL 绑定参数且明确处理逻辑删除。已审核详情使用业务快照，余额用当前档案名称，流水用记账快照。

执行 `scripts/apply-purchase-receipt-inventory.ps1` 增量建表、增加到货行字段、登记菜单及权限；重复执行不重置累计数、不覆盖业务数据。Compose 增加新数据卷初始化挂载。菜单为采购管理／采购入库单、库存管理／库存余额和库存流水，默认管理员授权。

## 验证

ReceiptIntegrationTest 使用生产 Mapper、事务、审计、方法权限及 MVC，覆盖完整链路、跨来源合并、货位拆分汇总、引用及竞态、并发占量、重复审核、同维度首次记账、精度、JSON、分页、余额溢出、库存不足、版本冲突和失败回滚；原有基础档案、订单及到货继续回归。真实 MySQL 和浏览器另行验证增量幂等、中文、货位入库、流水冲销、跨页参照和失败恢复。临时数据单独标记并在核对下游引用后清理，不提交前端测试宿主页及截图。
