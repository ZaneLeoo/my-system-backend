# 元数据驱动的查询框架

本期接入 `masterdata.item` 和 `purchase.order`。业务页采用常用区与高级条件，查询界面由已发布配置驱动；返回投影、权限和关联关系仍由业务适配器控制。没有个人或公共方案，没有自由 SQL、外部数据源、动态结果列或动态业务表 DDL。

## 管理操作

1. 系统工具 → 查询管理：直接进入数据目录并导入已登记表。中文名可编辑，不改数据库注释。
2. 同步先预览新增、变更、失效字段和引用对象，再按版本及结构签名确认。字段 ID 与人工名称保留。字段重命名不自动迁移。
3. 在数据目录对应表的“配置查询”操作进入查询对象编辑；主表、预设明细来源都能跳转，多个查询对象时选择目标。选择来源分组和物理字段，配置控件、运算符、选项来源、常用区和排序；常用区支持拖拽排序。已有字段标识及数据来源不可更换；改用新来源时停用旧标识并新增。
4. 保存草稿后切换到预览标签会自动加载，预览还要求相应业务列表权限。发布时复核实际数据库结构，事务内插入不可变快照、切换版本并递增草稿版本。
5. 发布后旧页面提交返回 `409`。刷新配置后必须明确调整或重置失效条件，不能自动删除条件扩大查询。

`sys_metadata_table`、`sys_metadata_column` 是物理目录；`sys_query_definition`、`sys_query_field` 是草稿；`sys_query_release` 保存不可变发布快照。目录通过可用状态保留失效记录，字段通过停用保留标识，不提供硬删除管理接口。所有配置实体继承 `AuditEntity`。增量 SQL 的初始审计账号为 `admin`；运行时修改必须由有效登录身份填充审计。

## 新业务接入

在业务模块实现 `QueryAdapter`，登记稳定编码、原列表权限、主表与受控关联、主键、默认排序、只读执行和选项提供器。`QueryRegistry` 发现重复编码时启动失败。元数据仅能导入适配器登记的当前应用数据库业务表；数据库新增普通字段可同步后配置，新增业务对象或关系需要开发接入。

适配器返回既有业务 VO，禁止通用查询直接返回任意数据库列。采购订单使用明细保存快照过滤，`EXISTS` 只判断是否有匹配行，不展开订单行；到货、入库进度仍通过当前页 ID 批量补齐。原有 GET 列表与编辑参照保留。

管理权限不代表业务权限。运行时元数据、选项、查询和草稿预览都使用当前登录用户的业务列表权限；查询选项包含停用、未删除档案，不复用编辑选择器的新选规则。发布快照按对象与版本缓存，当前发布指针每次从数据库读取；缓存命中也复核授权和字段有效性。

## 请求与语义

新增 POST `/masterdata/item/search`、`/purchase/order/search`，返回既有 `R<PageResult<T>>`。

```json
{
  "pageNum": 1,
  "pageSize": 20,
  "configVersion": 1,
  "filter": {
    "type": "group",
    "logic": "AND",
    "children": [
      { "type": "condition", "field": "status", "op": "eq", "value": "APPROVED" },
      {
        "type": "relation", "relation": "lines", "mode": "EXISTS", "logic": "AND",
        "children": [
          { "type": "condition", "field": "lineItemName", "op": "like", "value": "台灯" },
          { "type": "condition", "field": "lineQuantity", "op": "gt", "value": "100" }
        ]
      }
    ]
  }
}
```

同一关联组中的条件必须命中同一明细行，独立关联组可命中不同行。`NOT_EXISTS` 表示不存在满足条件的行，与“存在不等于某值的行”不同。强制逻辑删除谓词在整个用户表达式外按 AND 加入。

文本、整数、十进制字符串、布尔值、日期、北京时间日期时间严格按类型转换。零及 false 是有效条件。普通空输入由前端省略；空文本与 NULL 分别使用 `isEmpty/isNotEmpty`、`isNull/isNotNull`；SQL 不等于不自动包含 NULL。区间两端必填且包含端点，日期时间使用 `yyyy-MM-dd HH:mm:ss`。模糊查询将 `%`、`_`、`!` 转义，用户不能自行添加通配符。`descendantOf` 只由分类提供器实现。

常用区和列筛选共用基础条件，高级条件独立保留，三者最终按“强制条件 AND 基础条件 AND 高级条件”执行。同字段高级条件不会被基础输入覆盖。列表只接受最新请求；失败恢复成功数据和查询指示，刷新及保存使用已生效条件。

## 安全与性能

字段名只来自已批准的元数据和受控来源；所有用户值交给 MyBatis 参数绑定，禁止客户端表名、别名、SQL、函数和表达式。删除标记、技术版本、密码、盐、Token 等字段不进入可配置目录。排序仅允许已发布主表字段，追加主键稳定排序。

限制：30 个有效条件、3 层逻辑组、3 个关联组、关联不嵌套、每个集合 1～100 项，默认每页 20 条且最大 100 条。页码最大 100000。分类后代展开最多 10000 个节点，不计为客户端 IN 输入。

新查询 Mapper 语句超时为 3 秒，PageHelper count 继承超时；新查询与预览的客户端超时为 15 秒。MySQL 实测百万明细下三个无匹配关联 OR 的 count 被取消并返回业务码 408。慢查询日志只记录对象、发布版本和耗时，不记录输入值；关闭新增查询 Mapper 的 DEBUG 参数日志。

十万订单／百万明细的独立测试库验证中，料品关联完整 API 查询（含 count 和进度）约 600ms；纯 SQL 日期分页约 2～4ms，料品关联分页约 27～60ms，关联 count 约 25ms，模糊匹配的复杂 OR count 约 2.5s。这是本机测试记录，不是其他数据分布和硬件上的时延保证。已有订单日期、明细归属和料品索引可覆盖代表性查询，本期未批量增加索引。

## 迁移与兼容

运行 `scripts/apply-query-framework.ps1`；新数据卷依次挂载 `20261019_01_query_framework.sql` 和 `20261019_02_query_navigation.sql`。重复运行不重建数据库、不覆盖已发布配置及人工修改。脚本会启用若依内置的“系统工具”目录，并将两个旧页面菜单收敛为单一“查询管理”菜单，原按钮权限和角色授权保留；同时只登记当前数据库元数据、默认查询配置与菜单，不生成业务数据。

元数据和发布规则测试在新查询模块；原业务测试继续运行。远程参考库只做过只读结构检查，其地址和凭证未加入项目配置。个人／公共方案将在后续单独设计，存储字段逻辑标识与表达式，不保存 SQL 或共享数据访问权限。
