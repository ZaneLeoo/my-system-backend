# 仓库与货位

## 数据和维护规则

`md_warehouse` 保存仓库编码、名称、货位管理开关、状态、备注和版本；`md_location` 保存所属仓库、货位编码、名称、状态、备注和版本。两表继承公共审计和逻辑删除约定，使用 `utf8mb4_unicode_ci`，不建物理外键。

仓库编码全局唯一，货位编码在所属仓库内唯一；大小写不敏感，删除后保留占用，名称允许重复。货位所属仓库创建后不能更换。数量库存、业务引用和层级库区不在本轮范围。

货位创建和从停用重新启用时，父仓库须启用并开启货位管理。父仓库停用保留子货位自身状态，但新选参照全部不可用。停用仓库下的原有货位可修改、停用或删除。存在任何未删除货位时，不能删除仓库或关闭货位管理。

写入采用“仓库行锁 → 货位行锁”的固定顺序，持锁后以当前值校验。更新和删除要求旧版本；更新成功递增，旧页面拒绝。删除采用带实体的 MP 方法保证审计填充。当前不预造已使用标记；后续到货、入库和库存接入时需补充引用及货位管理方式变更限制。

## 接口与权限

维护接口为 `/masterdata/warehouse`、`/masterdata/location`，提供 `GET /list`、`GET /{id}`、`POST`、`PUT`、`DELETE /{id}?version=…`，分别检查 `list/query/add/edit/remove`，使用 `R<T>`。默认每页 20，最大 100，按编码升序；排序白名单为编码、名称、修改时间，追加 ID。货位列表必传 `warehouseId`。

`GET /masterdata/location/warehouse-context?warehouseId=…` 仅返回所属仓库的 ID、编码、名称、状态及货位管理开关。货位列表、查询、新增、修改或参照权限任一可读，不额外要求仓库维护权限。

只读参照接口为 `/masterdata/reference/warehouses`、`/locations`，支持关键词、接口分页和排序。对应 `/resolve?ids=…` 每次最多 100 个 ID，去重且保留请求顺序；货位搜索、回显必传仓库 ID，跨仓回显返回缺失。新选过滤启停及父仓状态，回显可保留未删除的停用记录。参照响应不包含审计、版本或删除标记。

参照权限分别为 `masterdata:warehouse:reference`、`masterdata:location:reference`。菜单位于基础资料的仓库档案，货位权限登记为其按钮权限，无独立货位菜单。默认仅管理员获授权。

## 初始化与验证

已有数据库运行 `scripts/apply-warehouse-location.ps1`；新 Docker 数据卷自动挂载 `sql/migrations/20261017_03_warehouse_location.sql`。脚本幂等，不覆盖已有记录或重建数据库，不预置演示档案。

`StorageIntegrationTest` 覆盖参数绑定与校验、审计、逻辑删除、同码与跨仓规则、版本冲突、独立参照权限、分页排序和锁竞争。交付同时执行现有模块回归，并以真实 MySQL 验证中文、排序规则、重复初始化及仅参照权限账号。
