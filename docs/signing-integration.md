# 电子签署接入说明

## 边界与版本

`my-system-signing` 以 Java 8 为语法、JDK API 及字节码基线。核心运行时不依赖 Spring、若依、MyBatis 或 JSON 库；Lombok 只参与编译。JUnit、Gson 仅用于兼容性测试。

宿主适配位于 `my-system-business/com.ruoyi.business.signing`：负责业务访问、权限、事务、数据库和私有文件。迁移旧项目时保留核心 JAR，并实现 SPI；Spring Boot 4 宿主代码不直接移入 Java 8 项目。

核心 `api` 是业务入口，`application` 编排状态和后台步骤，`spi` 是宿主扩展，`provider.esign` 是 V3 协议实现。公共模型不暴露平台数字流程状态，模板映射包含平台控件标识及类型，换平台后需重新绑定模板。

## 本机配置

1. 执行 `scripts/apply-signing.ps1`。新 Docker 数据卷已挂载增量 SQL；重复执行不会重建数据库或覆盖业务数据。
2. 在服务端配置 `.env.example` 中列出的 `SIGNING_*`、`ESIGN_*` 环境变量。调试 IDE 需将这些变量注入启动环境，配置文件不会自动读取任意 `.env`。
3. 沙箱和生产应用分开，`ESIGN_ENVIRONMENT` 为 `SANDBOX` 或 `PRODUCTION`；密钥不进入数据库、日志或前端。
4. 配置我方实名机构名称／ID；未配置机构 ID 时，通过官方认证查询按名称解析，返回名称必须一致且已实名。读取印章需要企业授予当前应用 `manage_org_seal` 权限，自动落章授权需另行核对。手动签署的我方经办人为当前用户，手机号取用户资料，不能冒用对方签署链接。
5. 配置公网 HTTPS `ESIGN_CALLBACK_URL`，准确指向 `/signing/callback/esign`。e签宝不会自动提供这个地址。本项目会在每次创建签署流程时传入 `notifyUrl`，所以无需再为相同的签署状态事件配置一份 Webhook；如果两处都订阅相同事件，平台会重复推送。签章位置通知仍需在开放平台“应用管理 → 我的应用 → 配置 → Webhook／消息推送”里添加相同地址，并订阅“获取签章位置信息”。位置回填走已验签回调，浏览器重定向不作为凭据。
6. 合同目录默认 `data/signing-private`，必须独立于若依公开 `ruoyi.profile`。正式部署要备份该目录并配置访问控制及存储加密；不使用 `/profile/**` 下载。
7. 本地应用需通过云服务器出站时，设置 `ESIGN_SOCKS_PROXY_HOST` 和 `ESIGN_SOCKS_PROXY_PORT`。保持受限 SSH SOCKS 隧道运行；云服务器 HTTPS 回调入口通过反向隧道转发到本地应用 8080，因此本地应用和隧道都必须运行。
8. 在你自己的调试进程中重新编译并启动应用；本次实现不启动或替换调试进程。

默认关闭集成及后台任务，配置缺失时页面明确提示；不能将关闭状态或模拟平台测试视为真实联调成功。

## 操作与接口

独立菜单为“电子签署 → 签署任务 / 合同模板配置”。签署任务支持按业务场景、平台流程状态分页查询，并从来源选择窗口发起。采购订单详情保留轻量的发起与历史入口；签署不阻塞到货或入库，不自动关闭订单。

业务扩展分为两层：`SigningBusinessAdapter` 提供资格校验、业务快照、字段目录和 `defaultCounterparty`；宿主 `SigningBusinessSupport` 提供业务名称、访问校验与可发起来源分页。通用控制器不引用具体订单 Service。前端只需在 `src/integrations/signing/businesses.ts` 登记返回来源的路由，业务页面调用 `beginBusinessSigning(router, businessType, businessId)`，模板和签署页面不导入采购 API。

`GET /signing/businesses` 返回场景目录及访问能力；`GET /signing/businesses/{businessType}/sources` 返回可签署来源；`GET /signing/tasks/list` 返回经过来源权限过滤的分页摘要。工作台的总数在授权场景过滤后计算，不暴露快照、联系方式或存储键。当前采购订单按功能权限开放全部订单；新增有行级隔离的业务时，必须同步实现工作台的行级过滤，不能仅把场景设为可访问。

对方机构、联系人和通知账号由适配器从任务保存的单据快照提供默认值。默认值只用于未保存签署方的初始化；用户必须确认保存，后续刷新不会覆盖已修改的签署人。默认联系人不代表已通过平台实名或用印授权。

- 模板：选择应用已有模板，使用官方编辑器维护版式；本地配置中文业务字段及动态表列映射。映射按控件 ID 和类型校验，主表与明细仅开放开发者登记字段。
- 文件：PDF、DOC、DOCX 原件最大 10MB；平台完成 PDF 转换后才可定位。准备后文件不可原地改写，重新生成会清除位置确认。
- 保存双方 → 官方拖章 → 刷新接收位置 → 确认最终文件与位置 → 第四步选择我方签署方式和印章 → 确认发起。新任务默认手动签署；手动可不预选，选定后限定这一枚印章。自动落章必须明确选择一枚启用的我方内部机构印章，不回退到平台默认章。对方保持手动签署并由平台短信通知；短信套餐需要在平台开通。
- 第四步的选择在发起时与任务、后台操作原子保存；发起前和后台创建前均实时核验印章。每方全部位置共用一枚所选印章。参与方保存接口不允许绕过发起命令改写用章设置；已创建流程只读。
- 印章弹窗支持类型筛选、每页八枚、单击单选、放大水印图片和失败重试。列表不包含个人、法人或外部授权章，未知类型和状态不可选；停用、待审核等状态只供查看。图片链接不进入响应、数据库或日志，鉴权图片接口禁止缓存。
- 签署状态：草稿、签署中、完成、撤销、过期、拒签；操作执行和本地文件保存状态独立。已完成后下载并私有保存正式文件。平台企业合同归档由 e签宝管理，本系统不主动操作或推断其归档状态；保留历史 `archiveStatus` 字段名，但页面只称“文件保存状态”。第六步为“签署结果”，流程完成以平台状态为准；文件保存中或保存失败不改变平台已完成状态，页面分别展示。
- 一单最多一个有效任务；本地草稿可取消并重新创建，创建未知结果不能取消或盲目重试。撤销、过期、拒签后允许重新发起，完成任务继续占用。

`/signing/tasks` 提供草稿、文件、双方、定位、发起、状态同步、撤销、取消、人工核对及文件读取。`/signing/templates` 提供平台模板、字段目录、绑定、编辑链接及试填。原始回调路径精确匿名，其余接口受签署权限和来源业务查询权限共同保护。

原有权限菜单 ID 与角色授权保留，迁移到独立电子签署菜单下：`signing:task:query/start/revoke/download/reconcile`、`signing:template:edit`，默认管理员拥有。

模板试填通过通用来源窗口选择满足发起资格的业务单据，必须具备该来源的查看权限；只生成预览，不发起流程。平台异步生成尚未就绪时会明确提示稍后重试。

## 恢复与数据

六张签署专用表保存任务、文档、当前双方、模板映射、事件、持久化操作。关键业务关联、状态、版本及去重字段有独立索引，领域细节及业务快照保存在受控 JSON 中。

网络调用不在数据库事务内执行。创建不自动启动，先保存平台流程 ID，再排队启动；创建超时或进程中断，标记未知结果并冻结重复创建。管理员在平台核实后用“关联已核对的平台流程”登记 ID，服务端检查该流程包含当前最终文件后同步。核对操作不会直接把任务标记为完成。

`sign_job` 用数据库唯一活动槽位、租约令牌和版本检查避免并行执行及旧工作者回写。回调原始字节验签、幂等落库成功才返回 200，后续异步查询平台权威状态，终态不会回退。未知通知兼容忽略。后台显式记录技术账号，不伪造登录态。

回调同时接受 V3 的 `signFlowId` 与 SaaS API 标准版的 `flowId`。`GET_SEAL_POSITION` 会校验当前定位会话、文件和控件后回填签章坐标；`SIGN_MISSON_COMPLETE`、`SIGN_FLOW_COMPLETE`、`SIGN_FLOW_UPDATE`、`SIGN_FLOW_FINISH` 只触发平台权威状态查询，不直接信任回调中的状态值。

已签文件和快照保留历史；取消本地草稿不删除文件。私有目录写入成功而数据库提交失败时，可能留下无引用文件，清理前需与 `sign_document` 全量核对。签署完成不等于合同法律解除；完成合同的解约不在一期范围内。

## 验证

- `scripts/maven.ps1 verify`：全量后端回归及 Spotless/Checkstyle。
- `scripts/verify-signing-java8.ps1 -Java8Home <JDK8目录> -Https`：真实 Java 8 核心测试、JSON、文件流及公开文档站 HTTPS 检查。不会调用签署业务接口。
- `scripts/verify-signing-mysql.ps1`：Docker 中创建独立临时库运行签署事务、版本、并发和恢复测试，退出后仅删除该随机临时库。不会向业务库添加测试合同。
- 前端执行格式、Lint、生产构建及类型错误基线对比。

真实文件转换效果、模板动态表、短信、自动盖章、定位回调、平台拒签／撤销及最终文件保存，仍需配置沙箱后逐项验收。浏览器测试必须逐次取得用户授权。
