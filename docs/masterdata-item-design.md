# 料品档案一期

`md_item` 对应一编码一种规格的实物料品，代码位于 `my-system-business/masterdata.item`。编码清理首尾空白后大小写不敏感唯一，删除后仍占用；名称允许重复。分类支持任意启用层级，库存单位必填，采购、销售单位独立可空。

实体继承 `BusinessEntity`，使用公共审计、逻辑删除和 `EnableStatus`。`version` 是并发版本，不是物料修订版本。税率采用百分数，范围 0～100、最多两位小数；null 表示未设置，与 0 不同。采购单位、销售单位和税率采用 MP `FieldStrategy.ALWAYS`，保证修改时可以清空。所有关联均由服务层校验，不使用物理外键。

## 接口和权限

接口前缀 `/masterdata/item`，权限前缀 `masterdata:item`。列表返回 `R<PageResult<ItemView>>`，详情及新增返回 `R<ItemView>`，修改、删除返回 `R<Void>`。

| 路径 | 方法 | 权限 |
| --- | --- | --- |
| `/list` | GET | list |
| `/{id}` | GET | query |
| 空路径 | POST | add |
| 空路径 | PUT | edit |
| `/{id}?version=…` | DELETE | remove |
| `/category-options`、`/unit-options` | GET | list/query/add/edit 任一权限 |

保存 DTO 不包含审计字段和删除标记，新增拒绝 ID、版本。编辑和删除必须传入最新版本；成功编辑递增版本。操作日志沿用若依。选项包含停用记录，单位选项不分页，不要求分类或单位维护权限。

查询条件按 AND 组合：编码、名称、规格包含文本；分类包含自身及后代；三种单位、启停、允许采购精确匹配。排序仅接受 `itemCode/itemName/specification/updateTime` 和 `asc/desc`，追加 ID 保持稳定。关联查询一次补齐分类及单位名称，分类路径通过一次分类索引构造，避免逐行请求。手写 SQL 显式过滤逻辑删除，筛选值使用绑定参数。

## 引用与事务

`masterdata.common.mapper.MasterDataReferenceMapper` 集中查询料品引用，分类、单位 Service 不依赖料品 Service。

- 启用料品引用的分类和任一角色单位不能停用。任何未删除料品的引用均阻止删除，包括停用料品。
- 新建或替换引用要求未删除且启用。停用料品可保留原有停用引用；重新启用重新检查全部引用。
- 料品新增、修改先取得现有分类树事务锁，再按单位 ID 升序进行当前读并持有行锁；修改随后锁定料品行检查版本。删除持有分类树锁和料品行锁。
- 分类写入继续使用分类树锁。单位修改、删除的第一条查询取得单位行锁，然后读取版本及引用；单位状态校验使用持锁后的当前读，防止等待行锁前的旧快照穿透。
- 当前没有单据，不添加虚假“已使用”字段；接入单据和库存后再限制基本单位变更并设计快照。

三个单位允许不同，本期没有换算关系。后续单据必须拒绝跨单位数量转换，不能暗含 1∶1。库存余额、最新价格和成本应来自业务单据，不保存在本档案。

## 初始化与验证

已有数据库运行 `scripts/apply-item.ps1`；脚本为 `sql/migrations/20261016_01_item.sql`，同时挂载到新 Docker 数据卷的第五个初始化入口。重复执行不重建数据库、不覆盖菜单、不预置演示料品。菜单位于“基础资料 → 料品档案”，默认分配管理员，新增菜单后重新登录。

`ItemIntegrationTest` 使用实际 Mapper、审计、事务、MVC 和 PageHelper，覆盖字段、可空清除、唯一性、分类后代分页、白名单、版本、引用、权限及竞态。既有分类、单位集成测试补齐关联表和公共引用 Mapper。真实 MySQL 与浏览器检查使用忽略目录中的临时数据，完成后按本次创建 ID 与专用编码清理，不提交测试脚本、截图和 Demo。
