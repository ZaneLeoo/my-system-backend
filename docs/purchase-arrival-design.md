# 采购到货单一期

## 单据及来源

业务位于 `my-system-business` 的 `purchase.arrival`。一张到货单对应一个供应商，表头可选填一个预计入库仓库，允许合并该供应商多个已审核采购订单。每行必须关联稳定的订单行 ID，同一张到货单不允许重复来源行。一个订单行可以分批到货，一期禁止超量和单位换算，每张到货单最多 200 行。

`purchase_arrival` 保存单号、实际到货日期、供应商与预计入库仓库快照、送货单号、首次创建人的经办与部门快照、状态、版本、备注和提交／审核／作废记录。`purchase_arrival_line` 保存来源订单及行 ID、来源快照、料品和单位快照、本次数量、来源数量精度及行备注。数量用 BigDecimal 和十进制字符串传输，超出来源精度拒绝保存。主明细均继承 BusinessEntity，明细稳定行 ID 供后续入库引用。

新单号由 `PA`、北京时间创建日期、自增 ID 组成，允许断号。到货日期不得早于任何来源订单日期。供应商、料品、分类和单位须有效且启用；预计入库仓库选填，填写时须有效且启用，料品须允许采购。料品及单位名称从来源订单快照带入，已审核到货历史不受档案更名影响。

到货不产生库存，不设货位、价格、金额或混合计量单位的总数量。不包含质检、入库、退货及审批引擎。

## 提交、审核与订单反写

订单行新增 `pending_arrival_quantity`（待审核到货）和 `arrived_quantity`（已确认到货），均默认零。可新增到货 = 订单数量 - 待审核到货 - 已确认到货。数据库 CHECK 保证两个累计数非负且合计不超订单数量。

| 操作 | 状态 | 对来源数量的影响 |
| --- | --- | --- |
| 保存、修改 | 草稿 | 不占额度，校验当前可用量 |
| 提交 | 草稿 → 已提交 | 增加待审核数量 |
| 撤回、驳回 | 已提交 → 草稿 | 释放待审核数量，驳回必填原因 |
| 审核通过 | 已提交 → 已审核 | 释放待审核数量，增加已确认数量 |
| 作废 | 已审核 → 已作废 | 冲减已确认数量，必填原因 |
| 删除 | 仅草稿 | 主明细实体逻辑删除，无数量反写 |

`ArrivalService.transition` 是统一业务生效入口，人工接口及未来审批结果均应进入同一业务命令。每个命令校验旧状态和版本，状态、行累计数量、来源订单版本及审计在同一事务提交。回调接入时需增加流程实例关联及事件幂等，不直接在回调控制器写累计数。

采购相关写入先取得既有分类树事务锁，再结合按 ID 排序的来源订单／明细锁、到货单锁和仓库行锁。仓库维护与到货写入通过仓库锁协调。重复审核、旧页面和并发争抢剩余额度不能重复反写。来源订单每次命令递增一次版本，故旧页面关闭订单需刷新。

订单进度按每行判断“未到货、部分到货、全部到货”，不加总不同单位，查询时计算，不新增持久化进度字段。全部到货不自动关闭订单。存在草稿或已提交到货时禁止关闭来源订单；已关闭订单不允许新增、提交到货，已审核到货仍可继续后续入库。作废不自动重开订单。

公共引用组件同时检查订单和到货，来源订单关闭后，尚待入库的有效到货仍阻止相关档案停用。任何未删除到货（含作废单）保留历史删除约束。本期无入库表，因此不设置虚假的入库标志；入库上线时必须补充下游草稿及正式单据阻止到货作废的约束，并调整待入库引用范围。真实退货走后续退货单，不使用作废代替。

## 接口与权限

维护前缀 `/purchase/arrival`，统一返回 `R<T>`，权限前缀 `purchase:arrival`。

| 接口 | 权限后缀 |
| --- | --- |
| GET /list | list |
| GET /{id} | query |
| GET /defaults | add、edit 或 query |
| POST、PUT | add、edit |
| DELETE /{id}?version=... | remove |
| POST /{id}/submit、withdraw、approve、reject、void | 对应动作 |

列表分页默认 20、最大 100，支持单号、供应商、仓库、状态、日期范围、来源订单筛选。排序仅允许单号、到货日期、修改时间，追加 ID 保持稳定。分页总数在转换前保留，线程上下文 finally 清理。

独立的 `purchase:order:reference` 权限访问 `/purchase/order/reference-lines` 及 `/resolve?ids=...`，不依赖订单列表／详情权限，不返回价格金额和审计信息。参照支持订单号及料品编码、名称、规格搜索，只返回已审核且仍有额度的行；确认前每次最多复核 100 个不同 ID。占用以正式提交时为准。

菜单为“采购管理 → 采购到货单”，管理员默认授权，其他角色分配到货动作、来源订单参照、供应商和仓库参照权限。沿用若依操作日志，不建立业务历史子表。

## 增量与验证

已有数据库执行 `scripts/apply-purchase-arrival.ps1`，新增两表、订单执行字段、菜单和权限。MySQL 使用元数据检测列及约束，重复执行不重置执行数和已有数据。新数据卷通过 compose 初始化挂载，不预置演示单据。

ArrivalIntegrationTest 使用生产 Mapper、审计、事务、方法权限及 MVC，覆盖两阶段反写、撤回驳回作废、并发提交和重复审核、版本溢出后整单回滚、多订单合并、精度、快照、关闭限制、独立参照权限、分页和排序白名单。原有分类、单位、料品、供应商、仓储及采购订单同时回归。前端与真实 MySQL 的联调使用临时验证档案及订单，验证后清理。

到货单仓库表示预计入库目标；到货单本身记录实际到货数量与日期，不等同到货预告。入库参照时默认带入此仓库，允许明细改选、拆分到其他仓库；实际库存以已审核入库明细为准，不以到货仓库记账。

预计入库仓库可省略或清空，不影响到货保存、提交及审核。清空时仓库 ID 写入 NULL，编码和名称快照写入空字符串，不保留旧仓库。参照未指定仓库的到货行时，入库明细不预填仓库，必须补选实际仓库后才能保存。执行 `scripts/apply-arrival-optional-warehouse.ps1` 兼容已有数据库；Compose 新卷按顺序执行 20261018_04 增量，重复执行不修改业务数据。
